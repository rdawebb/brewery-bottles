# brewery-bottles

Homebrew bottles for Intel Macs, built for
[brewery](https://github.com/rdawebb/brewery) to pour where homebrew/core no longer ships one.

## What's built

The **Intel `sequoia` gap**: formulae whose current version and revision have no official
macOS x86_64 bottle and no `:all` bottle. Everything else comes from homebrew/core as
usual. A daily CI run diffs homebrew/core against `index.json`, builds what's missing on
`macos-15-intel`, and publishes the results.

- **Tag:** `sequoia` only. Intel Tahoe pours these too. Intel Sonoma and earlier are not supported.
- **Blobs:** GHCR, in Homebrew's OCI layout (an image index tagged `<pkg_version>[-<rebuild>]`, with
  brew's `sh.brew.*` annotations), at `ghcr.io/rdawebb/brewery-bottles/<image>`. Image
  names match Homebrew's (`@` → `/`, `+` → `x`), so `python@3.13` is `python/3.13`.
- **Index:** `https://rdawebb.github.io/brewery-bottles/index.json` on GitHub Pages.

## Trust model

- Brewery checks each tarball against the `sha256` in `index.json`, the same trust model as its
  homebrew/core path.
- Every bottle has a GitHub artifact attestation (build provenance).
- Every index row and image annotation carries the formula's source URL, for licences that require
  a source offer.

## `index.json` (the contract)

Brewery reads this file and fetches blobs by digest. It never reads the GHCR manifest. Any changes to
this will be a breaking change and a `schema` bump. The file is generated by `brewery-bottles` CI and
published to GitHub Pages.

```json
{
  "schema": 1,
  "generated_at": "2026-11-01T00:00:00Z",
  "tag": "sequoia",
  "root_url": "https://ghcr.io/v2/rdawebb/brewery-bottles",
  "bottles": {
    "<name>": {
      "version": "1.2.3",
      "revision": 0,
      "rebuild": 0,
      "sha256": "<tarball sha256, also the blob digest>",
      "cellar": ":any_skip_relocation",
      "image": "<name with @ → />",
      "source_url": "<formula's stable source URL>",
      "tab": { "...": "the tab from `brew bottle --json`" }
    }
  }
}
```

- A blob is at `<root_url>/<image>/blobs/sha256:<sha256>`.
- Rows are only ever added or replaced on a version bump, never pruned. Brewery matches an exact
  `version`, `revision` and `rebuild`, so a stale row is harmless.
